A little help, right here.

Keep working pages in place. Give exploration its own destination.

Get connected first.

Pin the actual webpage tab, not just Anchor's toolbar icon. Open the popup and confirm protection is connected. Refresh webpages after extension updates. An ON badge requires an acknowledged current-page guard; a connection warning is not protection.

Choose where links go.

The popup supports New tab in this window, A new window for each link, and My browsing window. Follow the link or Stay here controls focus separately. Window & tab controls lets you designate your current normal window as the ordinary browsing destination. No existing browsing tab is overwritten.

Make one page a dashboard.

Make dashboard window moves the existing page into its own normal window when necessary and creates a saved solo workspace. It does not deliberately reload the page. The original window is reused for browsing when other tabs remain there.

Arrange two to four dashboards.

Open Workspaces, add existing pages or saved home URLs and choose a layout. 2 × 2 means four real Chrome windows, not four panes in one window. One window means multiple normal protected tabs with only the active tab visible. Save stores the definition; Open & arrange applies it; Arrange open pages refuses to reopen missing pages. A cell smaller than 480 × 320 is rejected. Actual sizes and focus can be adjusted by the OS.

Keep control.

Pause 5 minutes for maintenance and sign-in. Release workspace restores earlier tab choices without closing, navigating or unpinning pages. A pinned page can remain protected by the normal default after release. Closing a dashboard never triggers automatic reopening. Moving one out releases workspace membership instead of snapping it back.

Native tabs and sign-in.

Reserved windows move supported newly created extra tabs intact to the chosen outside destination. This can cover Cmd/Ctrl-click, middle-click and new-tab links. A tab can briefly appear before moving. Likely sign-in tabs, privileged browser pages, ambiguous blank tabs and deliberately dragged-in tabs are not forcibly moved. Pause proactively when authenticating; no heuristic recognizes every login flow.

What is not locked?

Address-bar navigation, automatic redirects, custom JavaScript buttons, reload, back/forward and arbitrary SPA state changes are not universally blocked. POSTs, password/file forms, downloads and protocol links stay native. Same-frame iframe navigation is native. Pinning and messaging are asynchronous: an immediate click before a previously unprotected page receives its new state can escape. Check connected readiness rather than treating pinning as a synchronous security boundary.

Experimental recovery.

Selected address-bar/bookmark/link/start-page navigation recovery is off by default. It can attempt to reload the former URL once until re-armed, but cannot restore unsaved state and does not automatically replay POST/auth/SPA operations. Working copy likewise opens an address, not a clone of the page's memory.

Interrupted operations.

If a browser action cannot be confirmed, Anchor does not blindly repeat it or navigate your original page as fallback. Check open windows, then review the pending-operation notice in Workspaces. Acknowledging an uncertain operation allows a retry; it is not proof that the earlier action did nothing.

Local storage and exports.

Home URLs can contain private paths or tokens. Review exports before sharing them. Preferences and workspace definitions are local; live tab bindings are session-only. Restarting the extension/browser can invalidate bindings. Open may then create new pages from saved URLs instead of matching other tabs by guesswork.

Testing and feedback.

This development handoff includes policy/worker tests, browser-rendered UI checks and a runnable installed-browser suite. Installed-extension acceptance was blocked by the managed test environment, so local Chrome and real dashboard acceptance remain required before publication. Report version, browser/OS and redacted reproduction steps; never send credentials.
